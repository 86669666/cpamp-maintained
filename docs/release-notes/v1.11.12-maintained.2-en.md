# CPA Manager Plus v1.11.12-maintained.2

> [中文 ->](https://github.com/86669666/cpamp-maintained/blob/v1.11.12-maintained.2/docs/release-notes/v1.11.12-maintained.2-zh.md)

## Overview

This maintained release closes the formal release-chain gaps left after retiring the legacy CPAMC repository. GitHub Releases now build the maintained Lightweight single-file panel directly, publish complete provenance metadata and checksums, and verify tag, source commit, and artifact identity both before and after artifact transfer.

## Highlights

### Release provenance and assets

- The formal Release workflow invokes `scripts/build-maintained-lightweight.sh`, rejecting dirty worktrees, ignored environment files, and unauthorized Vite environment injection.
- Releases publish `management.html`, `metadata.json`, `SOURCE_COMMIT`, `SHA256SUMS`, and native packages; the publishing job downloads the artifact and independently verifies checksums and provenance fields.
- Real tag runs refetch the remote tag during both build and publish stages and require the tag commit, `GITHUB_SHA`, `SOURCE_COMMIT`, and metadata to match exactly.

### Maintained-fork boundaries

- The private maintained repository uses `main` as its single release source and no longer incorrectly depends on a nonexistent `dev` branch topology.
- Publishing to upstream `seakee` DockerHub or GHCR namespaces has been removed, preventing inaccessible upstream registries from blocking the private fork's GitHub Release.
- Dry-runs create only a local synthetic tag and never publish a GitHub Release or send a Telegram notification.

### Regression gates

- The root test command covers the full Web and repository-level suite, including CPA/sub2api `type=apikey` conversion, plugin fail-closed behavior, architecture boundaries, and Release workflow integrity.
- Maintained-main tag topology tests were added, and CI locks out reintroduction of upstream container namespaces.

## Upgrade Notes

- This release changes only the maintained repository's release and evidence chain. It does not stop or replace the running CPA Manager Plus Full Mode service.
- Existing backup and recovery boundaries for `usage.sqlite`, `data.key`, management keys, and the service binary remain unchanged.
